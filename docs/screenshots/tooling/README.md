# Reproducing the screenshots

Everything in [`docs/screenshots/`](../) was generated by the scripts in this folder. If a
screen changes, or you want the set at a different size, you re-run these rather than
retaking anything by hand.

Nothing here touches the application. The Ruby scripts issue `UPDATE`s against a local
development database; the JavaScript drives a browser and writes PNGs. `db/seeds.rb`,
`app/`, `config/` and `lib/` are never modified.

## What each file does

| File | Runs where | Purpose |
| --- | --- | --- |
| `finish-csv-import.rb` | container, `rails runner` | Completes the seed's CSV import when it aborts (see below) |
| `relabel.rb` | container, `rails runner` | Rewrites the seed's placeholder text into plausible French coursework, then reindexes Elasticsearch |
| `facts.rb` | container, `rails runner` | Emits `facts.json`: the slugs, IDs and accounts the capture script needs, so no URL is guessed |
| `capture.js` | host, Node | Drives Chromium through every screen and writes the PNGs plus `manifest.json` |
| `gen_docs.js` | host, Node | Regenerates `GALLERY.md` and the README's showcase block from `manifest.json` |

Captions live in `capture.js`, next to the shot each one describes. That is deliberate:
`GALLERY.md` and the README section are both generated, so a caption is written once and
cannot drift between the two.

## Prerequisites

1. The app running at `http://localhost:3000`, following
   [Running it locally](../../../README.md#running-it-locally) in the main README —
   through step 9, including the Elasticsearch reindex.
2. Node on the host, and Playwright's Chromium:

   ```bash
   cd docs/screenshots/tooling
   npm install
   npx playwright install chromium
   ```

## Two things the seed needs help with

**The CSV import is fragile.** `db/seeds.rb` ends by importing
`lib/seeds/posts/posts_test.csv`, whose rows hard-code course names such as
*"La Promise du voyeur"* — names the same file generates randomly with
`Faker::Book.title` under the `:fr` locale. When the random draw misses one,
`Course.find_by(name: …)` returns `nil` and seeding aborts with
`ActiveRecord::RecordInvalid: Course doit exister`. It usually succeeds, and fails often
enough to be worth knowing about.

Those ten rows matter: they are the uploads belonging to the three test accounts. Without
them the accounts have no contributions at all. So run this after seeding, every time — it
is idempotent and does nothing when the import already completed:

```bash
docker compose cp docs/screenshots/tooling/finish-csv-import.rb web:/tmp/f.rb
docker compose exec web bundle exec rails runner /tmp/f.rb
```

**The seed text is placeholder data.** Document titles come from
`Faker::BossaNova.song`, descriptions from a V for Vendetta quote generator, course names
from `Faker::Book.title`, and tags from `Faker::Nation.language`. A feed full of bossa nova
song titles makes for meaningless screenshots, so `relabel.rb` rewrites those fields into
plausible French academic content and reindexes:

```bash
docker compose cp docs/screenshots/tooling/relabel.rb web:/tmp/r.rb
docker compose exec web bundle exec rails runner /tmp/r.rb
```

It leaves alone everything that already reads correctly: the 203 generated students, the
ten French institutions, the eight categories, the seven academic years, the study levels,
and the ten CSV documents' titles. It rewrites their descriptions, because the CSV's own
`description` column is English filler.

The screenshots therefore show generated demo content. They are real pages rendering real
records — just not real student uploads.

## Capturing

```bash
# 1. Collect the URLs and accounts to visit
docker compose cp docs/screenshots/tooling/facts.rb web:/tmp/facts.rb
docker compose exec web bundle exec rails runner /tmp/facts.rb \
  > docs/screenshots/tooling/.work/facts.json

# 2. Capture (~5 minutes, writes 59 PNGs and 3 annotated variants)
cd docs/screenshots/tooling && npm run capture

# 3. Regenerate GALLERY.md and the README showcase block
npm run docs
```

`npm run docs` writes `GALLERY.md` in place and leaves the README block in
`.work/readme_showcase.md` for you to paste in, so it can never clobber hand-written README
prose.

Capture settings, if you need to change them, are all near the top of `capture.js`:
1440×900 viewport, `deviceScaleFactor: 2`, and a height cap of 2600 CSS pixels. The cap
matters — the blog index is over 22,000 pixels tall unclipped, which is both unreadable and
a 5 MB file.

## Annotated variants

Three screens carry logic a static image cannot show. Those get a second `-annotated`
version with numbered callouts, produced by injecting an overlay into the live DOM
immediately before capture rather than by editing pixels afterwards — so the annotation
stays crisp at 2× and the clean original survives as its own file.

To annotate another screen, add a call next to its `shot(…)`:

```js
await annotate(page, 'feed-01', [
  { selector: '.card', text: 'What this element does.' },
], 'Legend title');
```

The selector accepts CSS, or `text=<substring>` to find an element by its content.

## A caveat on the download counter

The reciprocity gate is triggered by performing three real downloads as a student with no
uploads, so the counter is incremented by `DownloadsController` rather than written
directly. Chromium does not reliably raise a download event for that POST-then-redirect, so
the script does not wait for one — the gate appearing on the fourth page is the proof that
the requests landed.
